\subsection{Software testing fundamentals}
Software testing is a fundamental part of developing software systems, and it is used to verify that the system behaves as expected and that its requirements are fulfilled. In software testing, there are primarily three levels of testing, including unit testing, integration testing, and system testing. Unit testing focuses on individual components of the system, integration testing focuses on multiple components working together, while system testing focuses on the system as a whole.

System testing is often performed as black-box testing, which means that only the system interfaces are tested and based on the requirements, it is examined whether the system fulfills its expected behavior. From the requirements, test cases are defined as a sequence of actions to be performed during testing, including the necessary execution steps and the expected results for each step \cite{testing_study_2020}.

A related concept is end-to-end testing. End-to-end testing usually focuses on complete flows through the system, for example from user input to final output. This is similar to system testing in the sense that both look at the behavior of the full system. However, system testing is broader and focuses more generally on whether the whole system meets its specified requirements. For this reason, system testing is the more suitable concept in this project \cite{istqbE2E}.

System testing can also be challenging. Whittaker \cite{whittaker2002software} explains that software testing is difficult because software behavior can be complex and because testers must consider many possible situations, inputs, and interactions. In larger systems, this becomes even more demanding, since the complete system may include many connected parts, dependencies, and possible execution paths. This makes it difficult to test everything fully in practice.

This is relevant to the present degree project because the project focuses on generating system test cases from requirements. The purpose is not to test single units of code, but to support the creation of test cases that can verify the behavior of the complete system based on written requirements. Since system testing is closely connected to requirement fulfillment, it provides an important theoretical basis for this study.

\subsection{Model-based Testing}
Model-based testing (MBT) is a testing approach where test cases are generated from a model of the system instead of being created manually. The model describes the expected behavior of the system, and the generated test cases are based on that model. Dalal et al. \cite{dalal1999model} describe model-based testing as a way of generating test cases from requirements by using models of the system behavior. This makes the testing process more systematic and supports a higher degree of automation. In the same direction, Pretschner explains that model-based testing relies on models or specifications that encode the intended behavior of a system, and that runs of the model can be interpreted as test cases \cite{pretschner2005mbt}.

A central idea in MBT is therefore that the model represents how the system is expected to behave, and that test cases are derived from this representation. This makes the testing process more systematic and can support a higher degree of automation than fully manual test design \cite{dalal1999model,pretschner2005mbt}. El-Far and Whittaker also describe model-based software testing as an approach where models are used to guide test selection and test verification \cite{elfar2001mbst}.

MBT is useful to this degree project because it represents an established approach to automated test generation. At the same time, it also shows an important difference compared to the present study. In MBT, the generation of test cases depends on having a model that represents the intended system behavior \cite{pretschner2005mbt}. In this degree project, the focus is instead on generating system test cases directly from written requirements by using a large language model (LLM). For this reason, MBT can be seen as a useful background and comparison point for the present work.
